# SPHEREx 3D — verified regional archive + illustrative global sky

The `SPHEREx 3D` tab has two clearly separated data modes behind one renderer:

| Mode | What is on screen | Status |
| --- | --- | --- |
| **NEP ARCHIVE** (default) | The two verified, reprojected SPHEREx QR2 observations of the North Ecliptic Pole, on one agreed tangent plane | Real archive products |
| **ILLUSTRATIVE** | Four deterministic global epochs in a HEALPix NEST pyramid | Visualization prototype |

The tab remains separate from the validated `SPHEREx FIELD` tab. The FIELD
workflow and its product gate are unchanged.

## Scientific status

The repository contains two real reprojected SPHEREx NEP observations under
`data/spherex/derived/` (`epoch-a`, `epoch-b`). They are the only archive
observations available in this checkout. It does **not** contain a four-epoch
all-sky archive.

Archive mode therefore shows exactly one regional tangent plane. Every pixel
outside that plane is rendered as an explicit no-data surface, never as a
measured zero and never as a decorative starfield. The UI, index and raster
headers all say that this is regional, not full-sky.

The two archive epochs can be inspected one at a time on one reprojection grid
with one shared display stretch. There is **no** difference, subtraction,
variability statistic or motion measurement route or control. The
`SPHEREx FIELD` gate (`quantitative_difference_enabled: false`) is unchanged,
and the archive index carries the same gate.

The four global epochs in illustrative mode are deterministic prototype data
generated by `server/spherex/sky-tiles.js`. The page labels them illustrative in
the HUD, provenance card and API (`mode: "illustrative"`).

## What the server serves

| Route | Purpose |
| --- | --- |
| `GET /api/spherex/sky/archive` | Archive index: two verified epochs, surface geometry, shared stretch, provenance, gate |
| `GET /api/spherex/sky/archive/:epoch.png` | One real observation as a 294×294 RGBA TAN PNG |
| `GET /api/spherex/sky` | Illustrative index: four epochs, coverage, HEALPix NEST levels, URL templates |
| `GET /api/spherex/sky/sources` | GPU-instanced prototype candidate measurements for the four illustrative epochs |
| `GET /api/spherex/sky/base/:epoch.png` | 512×256 equirectangular RGBA illustrative base |
| `GET /api/spherex/sky/tile/:epoch/:order/:ipix.png` | 128×128 RGBA HEALPix NEST tangent-plane patch |

Archive epoch IDs are `epoch-a` and `epoch-b`. Illustrative epoch IDs are
`epoch-1` … `epoch-4`; tile orders are `1` (48 pixels) through `4` (3,072
pixels).

### Archive raster conventions

* One RGBA PNG per verified observation, at the agreed grid shape (currently
  294×294 at 6.15 arcsec/pixel).
* Image row 0 is north and column 0 is east; image columns increase west
  (`CD1_1 < 0`). The client builds a TAN patch whose `+u` axis is west and `+v`
  is north.
* `MASK != 1` or non-finite pixels have alpha 0. A missing measurement is never
  filled with black.
* One linear percentile stretch is computed over the valid pixels of **both**
  epochs and reused for both PNGs. Per-epoch auto-stretching would manufacture
  apparent brightness changes.
* The archive index records the archive release/DOI, observation ID, detector,
  UTC date, MJD, exposure, pipeline version, quality flags, archive and cutout
  URLs, cutout SHA-256, derived-output SHA-256, units, WCS and measured valid
  fraction.
* The response headers include `X-Novochar-Sky-Mode: archive`,
  `X-Novochar-Sky-Epoch`, `X-Novochar-Sky-Role`, the raster dimensions and the
  source SHA-256.

### Illustrative raster conventions

* Base: column 0 is RA 0, row 0 is Dec +90; the image is equirectangular.
* Tile: the centre is the HEALPix NEST pixel centre; east is the local `+u` axis
  and north is the local `+v` axis. The renderer reconstructs the same patch
  with `normalize(center + east*u*half + north*v*half)` and the same
  `tileHalfAngleRad(order)` as the server.
* Alpha 0 marks no-coverage model sky. The client draws an opaque hatched
  no-data shell behind the sphere so a gap can never reveal decorative stars or
  the page background.

The client decodes every PNG into an `ImageBitmap` that is **pre-flipped during
decode** (`imageOrientation: "flipY"`), then uploads it with `texture.flipY =
false`. WebGL ignores `UNPACK_FLIP_Y_WEBGL` for `ImageBitmap` uploads; without
the explicit flip the sky would be vertically mirrored. The contract is pinned
by `client/src/lib/sky-tile-decode.test.js`.

### Cache and error semantics

Raster routes send `Content-Type: image/png`, an `ETag`,
`X-Novochar-Sky-Mode`, `X-Novochar-Sky-Cached`, and
`Cache-Control: public, max-age=86400, stale-while-revalidate=604800`. A
matching `If-None-Match` returns `304` with no body. Invalid epoch/order/pixel
requests return JSON errors, never blank images. Archive index errors distinguish
an unknown epoch (404) from a temporarily unavailable product (503).

The PNG caches are in-memory and per process. Vercel's `/tmp` is not used as
durable storage.

## Client architecture

| File | Responsibility |
| --- | --- |
| `client/src/components/SpherexSky3D.jsx` | Mode switch, timeline, observation/candidate cards, performance HUD, FIELD bridge, error/WebGL2 states |
| `client/src/lib/sky3d-engine.js` | Three.js scene, camera controls, archive TAN patch, illustrative base/tiles, no-data shell, instanced candidates, adaptive DPR/detail, prefetch, disposal |
| `client/src/lib/sky-tile-loader.js` | Deduplicating priority queue, worker pool, abort/cancel, main-thread fallback, stats |
| `client/src/lib/sky-tile-worker.js` | Fetch + decode off the main thread |
| `client/src/lib/sky-tile-decode.js` | North-up `ImageBitmap` decode (the flip contract) |
| `client/src/lib/sky-tiles.js` | URL helpers, view-dependent LOD, nearest HEALPix pixels, LRU texture cache, device quality profile |
| `server/spherex/archive-sky.js` | Regional archive service, shared stretch, PNG rendering, provenance index, HTTP route |
| `shared/astro/healpix-nest.js` | One shared NEST implementation for server and client |

The engine renders on demand; it is not a free-running animation loop. Both
timelines default to paused.

Archive mode loads one texture per epoch and prefetches the other observation
when the device budget allows. There is no HEALPix refinement in archive mode
because there is no fabricated all-sky coverage behind the region.

Illustrative mode fetches the base texture first, then a central island of
order-2 tiles, then higher orders as the user zooms. Stale requests are
cancelled when the view or epoch changes; a small prefetch of the next epoch's
base and twelve base-order tiles runs only when the browser is idle and the
device is not in the low tier.

Quality profiles:

* **standard**: up to order 4, 192 textures, 2 workers, DPR cap 2, prefetch.
* **low** (coarse pointer, small viewport, `Save-Data`, ≤4 GB device memory or
  ≤4 logical cores): up to order 3, 128 textures, 1 worker, DPR cap 1.25, no
  prefetch.

Frame time drives a bounded DPR reduction and, on sustained slowness, a lower
illustrative detail order. The page also honours `prefers-reduced-motion` by not
autoplaying the timeline.

## Coverage and timeline semantics

Archive mode has two stops, named by UTC observation date. Its coverage numbers
are measured fractions of the agreed NEP grid (`valid_fraction` and
`covered_fraction`), not sky fractions. The surrounding sphere is no-data and is
labelled as such.

Illustrative mode has four epoch stops and shows a model-sky coverage fraction.
The illustrative model exposes representative gaps:

* epoch 1: full coverage;
* epoch 2: gap around RA 194–238°, Dec −1–23°;
* epoch 3: no coverage below Dec −66°;
* epoch 4: gap around RA 16–55°.

These are prototype coverage semantics, not archive coverage.

## Archive ingestion path

The regional archive adapter is the minimal end-to-end path. To extend coverage
to another verified region or a fuller sky:

1. Ingest archive products with their WCS, mask, units, calibration and
   provenance.
2. Validate the WCS, photometric calibration and mask; reject products that do
   not pass the same alignment gate used by `SPHEREx FIELD`.
3. Reproject each epoch onto the agreed frame, preserving one shared display
   stretch across comparable epochs.
4. Store the derived products as immutable, content-addressed files with source
   SHA-256s and generation metadata — not in `/tmp`.
5. Add a new regional index or extend the archive index with additional
   surfaces. Keep the raster conventions (`north-up`, alpha 0 for invalid) so
   the client contract stays stable.
6. Add acceptance checks that compare sampled pixels with the source
   measurements and fail if a raster is filled-in, mirrored or mis-registered.
7. Keep the real NEP detail layer in `SPHEREx FIELD`; do not replace it with a
   mosaic.

Do not claim four real epochs or full-sky archive coverage until that data is
verified and present.

## Deployment

The 3D routes do **not** need Python, the sidecar, a network fetch or `/tmp`.
They use the same Node server as the rest of the API; Vercel rewrites
`/api/:path*` to the function in `api/index.js`. The real NEP bundle remains
committed under `data/spherex/derived/` and included by `vercel.json` for the
FIELD and archive routes. Raster responses are CDN-cacheable.

## Verification

```bash
npm test                         # unit + contract tests
npm run build                    # bundle check + precompute + client build
npm run check:spherex3d          # browser acceptance (needs built client + Chromium)
npm run verify:deployment -- https://your-deployment.example
```

`check:spherex3d` boots the production server and checks:

* the archive index exposes exactly two verified epochs, a shared stretch, real
  provenance and no global-coverage claim;
* both archive PNGs carry the archive mode, epoch and source hash;
* the default 3D view is the archive region, with no fabricated all-sky base;
* switching archive epochs changes the real observation on screen;
* illustrative mode is a separate tab with four epochs, HEALPix detail, source
  markers, play/pause and reset;
* no difference/subtraction/variability control exists;
* the mobile low-quality path and no-WebGL fallback stay honest;
* the FIELD bridge lands in the validated tab without uncaught errors.
